# יבוא חד פעמי — חנות הזמנות בוואטסאפ

יש כאן **שני ערוצי הזמנה**, שאפשר להפעיל יחד או בנפרד:

1. **אתר קטלוג בעיצוב "צ'אט וואטסאפ"** — הלקוח גולל, לוחץ "הוסף", ובסיום לוחץ "שליחת הזמנה בוואטסאפ": נפתחת שיחת וואטסאפ עם המספר העסקי שלכם, עם הודעה מוכנה מראש. בלי צורך באישור מטא, עובד עם כל מספר רגיל.
2. **בוט הזמנות שרץ *בתוך* וואטסאפ עצמו** (`bot/`) — לקוח כותב לכם בוואטסאפ "היי", והבוט עונה אוטומטית עם תפריט, מוביל אותו דרך בחירת מוצרים וכמויות, ובסוף יוצר הזמנה לבד. הבוט מתחבר למספר הוואטסאפ העסקי שלכם ע"י **סריקת קוד QR** (בדיוק כמו וואטסאפ-web) — גם כאן בלי אישור מטא. פרטים מלאים ואזהרות חשובות בהמשך.

**בשני המקרים, כל הזמנה, לקוח ופרטי מלאי נשמרים במסד נתונים** (SQLite מקומי) — כך שיש לכם תיעוד מלא, גם אם ההודעה בוואטסאפ "הולכת לאיבוד". יש מסך ניהול (`/admin`) שבו ניתן לראות הזמנות (מסומנות מאיזה ערוץ הגיעו 🌐/💬), לקוחות, לעדכן סטטוס הזמנה ומלאי, לחבר את הבוט, ולשנות הגדרות.

## הרצה מקומית

```bash
npm install
cp .env.example .env
npx prisma db push   # יוצר את קובץ מסד הנתונים המקומי
npm run seed          # מאכלס נתוני דוגמה (קטגוריות + מוצרים)
npm run dev
```

האתר יעלה בכתובת http://localhost:3000, ומסך הניהול בכתובת http://localhost:3000/admin (סיסמת ברירת מחדל: `admin123`).

## הגדרה ראשונית — חשוב לפני שמשתפים לקוחות!

1. היכנסו ל־`/admin` → לשונית **הגדרות**.
2. עדכנו את **מספר הוואטסאפ העסקי** שלכם, בפורמט בינלאומי ללא `+` וללא `0` מוביל (למשל מספר ישראלי `050-1234567` הופך ל־`972501234567`).
3. עדכנו את שם החנות, הודעת הפתיחה, ואת **סיסמת הניהול** (שווה להחליף מ־`admin123`).
4. בלשונית **מלאי** אפשר לערוך מחירים, כמות במלאי, ולסמן מוצר כ"אזל".

> ⚠️ עד שלא תעדכנו את מספר הוואטסאפ, הזמנות ישלחו למספר דמה (`972500000000`).

## עריכת קטלוג המוצרים

נתוני הדוגמה הראשוניים נמצאים בקובץ `prisma/seed.ts`. אפשר:
- לערוך שם/כמות/סטטוס מלאי דרך מסך הניהול (`/admin` → מלאי).
- או לערוך את `prisma/seed.ts` ולהריץ שוב `npm run seed` (שימו לב: זה מוחק הזמנות ולקוחות קיימים ומתחיל מחדש — מומלץ להשתמש בזה רק בשלב ההקמה).

להוספת מוצרים/קטגוריות חדשות בלי למחוק נתונים קיימים — ניתן להוסיף זאת ישירות דרך Prisma Studio:

```bash
npx prisma studio
```

## הבוט שרץ בתוך וואטסאפ (`bot/`)

### איך זה עובד
כתבתי בוט שמתחבר לוואטסאפ **בדיוק כמו מכשיר נוסף מקושר** (Linked Device) — אותה טכנולוגיה שמפעילה את "וואטסאפ-web" בדפדפן. סורקים איתו QR מהטלפון העסקי פעם אחת, ומאותו רגע הבוט "יושב" על הקו ורואה הודעות נכנסות, בדיוק כמו שאתם הייתם רואים אותן בעצמכם — ויכול לענות אוטומטית.

### הפעלה
```bash
npm run bot
```
בפעם הראשונה יופיע קוד QR למסך הניהול (`/admin` → לשונית **בוט וואטסאפ**) — סורקים אותו מהטלפון העסקי דרך וואטסאפ ← הגדרות ← מכשירים מקושרים ← קישור מכשיר. התהליך צריך לרוץ **כל הזמן** ברקע (לא רק בזמן שמישהו מזמין) כדי שהבוט יקלוט הודעות נכנסות.

### ⚠️ שני דברים חשובים שכדאי להכיר לפני שמפעילים בעסק פעיל
1. **זו לא שיטת ההתחברות הרשמית של מטא** (זו לא WhatsApp Business API). זה בדיוק למה שלא צריך אישור/אימות עסקי — אבל זה גם אומר שמטא לא "בירכה" רשמית על השימוש הזה, ויש (סיכוי נמוך אך קיים) שחשבון עם הרבה פעילות אוטומטית יסומן. מומלץ לא "להפציץ" בהודעות ולבדוק את זה בהדרגה.
2. **צריך שרת שרץ 24/7**, לא רק את המחשב האישי שלכם. אם תסגרו את התהליך (`npm run bot`) — הבוט מתנתק ולקוחות שיכתבו לא יקבלו תשובה, למרות שהמספר עצמו עדיין מחובר לוואטסאפ הרגיל שלכם. כשתהיו מוכנים, אפשר להעלות את זה לשרת קטן שרץ תמיד (VPS, Railway וכו') — אני יכול לעזור עם זה.

### מגבלת עיצוב
בגרסאות עדכניות של וואטסאפ, חיבורים לא-רשמיים (גם הבוט הזה) לא יכולים לשלוח באמת "כפתורים" או "תפריטים" אינטראקטיביים שהלקוח לוחץ עליהם — זה פיצ'ר שדורש את ה-API הרשמי של מטא. לכן הבוט בנוי עם **תפריטים ממוספרים בטקסט עם הרבה אימוג'ים** (הלקוח שולח מספר, למשל "2") — זה עדיין מרגיש נעים וקל לשימוש, אבל זה לא לחיצת-כפתור אמיתית. תמונות מוצר כן נשלחות כתמונות אמיתיות אם הוספתם קישור תמונה למוצר (`/admin` → מלאי).

## איך זה עובד מתחת למכסה

- **Next.js (App Router) + TypeScript + Tailwind** לחזית ולשרת.
- **Prisma + SQLite** (`prisma/dev.db`) לשמירת כל הנתונים: מוצרים, קטגוריות, לקוחות, הזמנות, פריטי הזמנה, הגדרות חנות.
- כשלקוח שולח הזמנה: קודם היא **נשמרת בשרת** (`POST /api/orders`), ורק אז נפתח קישור `wa.me/<מספר>?text=<הודעה מעוצבת>` בטאב חדש — כך גם אם הלקוח לא שולח בפועל את ההודעה בוואטסאפ, ההזמנה כבר נשמרה אצלכם במערכת.
- מסך `/admin` מוגן בסיסמה (עוגיית session מוצפנת), ומאפשר צפייה ועדכון הזמנות/מלאי/הגדרות.
- **הבוט** (`bot/index.ts`) משתמש בספריית `@whiskeysockets/baileys` להתחברות לוואטסאפ, ושומר את מצב השיחה של כל לקוח (`BotConversation` ב-Prisma) כדי לדעת באיזה שלב הזמנה הוא נמצא. יצירת ההזמנה בפועל (`src/lib/orders.ts`) משותפת בין האתר והבוט — כך שכל הזמנה, מכל ערוץ, נשמרת באותו אופן.

## פריסה לאינטרנט (כדי שלקוחות יוכלו להזמין מהטלפון)

האתר בנוי כאפליקציית Next.js רגילה וניתן לפרוס בכל פלטפורמה שתומכת ב־Node.js (Vercel, Railway, Render וכו'). שימו לב: כברירת מחדל המידע נשמר בקובץ SQLite מקומי — בפריסה לענן מומלץ לעבור למסד נתונים מנוהל (למשל Postgres) כדי שהנתונים לא יימחקו בכל דיפלוי.

**חשוב:** האתר (`npm run dev`/`start`) והבוט (`npm run bot`) הם **שני תהליכים נפרדים**. פלטפורמות "serverless" כמו Vercel מצוינות לאתר אבל **לא מתאימות להרצת הבוט**, כי הוא צריך תהליך אחד שרץ ברצף 24/7 ומחזיק חיבור פתוח לוואטסאפ — לכן לבוט צריך שרת/worker קטן שרץ תמיד (למשל VPS זול, או שירות כמו Railway/Fly.io). אם תרצו עזרה בהגדרת פריסה מלאה — לאתר, לבוט, או לשניהם — ספרו לי ואני אעשה את זה בשבילכם.
